# UI Revamp Implementation Plan

> **For agentic workers:** execute surface-by-surface in order; each surface lands complete
> (both passes, screenshots, tests green, committed on its own branch) before the next starts.
> This plan deliberately does not script every visual decision — the brief's Part 10 process
> (build → screenshot → critique in writing → revise) is the design loop, and scripting pixel
> choices ahead of seeing them would fake precision. What IS locked here: scope, order, files,
> behavioural fixes, contracts, and the test that proves each surface.

**Goal:** rebuild every surface of Interlude to the standard in
[docs/REVAMP-BRIEF.md](../../REVAMP-BRIEF.md), shipped working against real data, polling and
degradation — never as mockups.

**Architecture:** no new frameworks, no component library, no new dependencies. Tailwind v4
tokens in `globals.css` grow duration/easing entries; screens stay server-rendered with the
one game client component; every behavioural fix lands inside the surface that owns it.

**Tech stack:** Next.js 16 App Router · TS strict · Prisma/Postgres · Tailwind v4 · Vitest ·
Playwright.

**Spec:** [docs/REVAMP-BRIEF.md](../../REVAMP-BRIEF.md), constrained by PLATFORM.md §5–§12,
UI-SPEC.md, and TODO.md's Done list. Conflicts and their resolutions:
[docs/REVAMP-NOTES.md](../../REVAMP-NOTES.md).

## Global constraints

- Compliance rules in full: no chance mechanics, review isolation (ESLint boundary + tests),
  control table ≡ closed venue byte-identical, purpose-limited consent, per-venue HMAC.
- Token discipline: no raw hex, no magic ms, no arbitrary values outside `globals.css` and the
  locked Tailwind scale. New this revamp: `--duration-state` (180ms), `--duration-reveal-hold`
  and one easing token; the three Poller intervals stay per PLATFORM.md §11.
- Accent ledger, exactly four: (1) won price on the guest rung/won screens, (2) primary button
  pressed state, (3) the single landing CTA, (4) onboarding stepper's active step marker.
  The `/floor` redemption-row accent drift is removed at Surface 4.
- Display face (Instrument Serif / Georgia fallback), exactly four, all ≥28px: (1) landing
  wordmark + h1, (2) `/dash` headline only when negative, (3) tent wordmark, (4) guest win
  heading. Two of these are currently unimplemented (tent, win heading); the landing steps h2
  is a fifth use and comes off.
- Every figure mono + `tabular-nums` — the recon audit lists 15 violation sites; all fixed in
  their surfaces, then re-audited.
- Motion: countdown is the only continuously moving element; rung reveal is the only staged
  moment (≤500ms, no bounce); three haptics (answer light, rung heavier, nothing on wrong,
  `navigator.vibrate` best-effort); no sound; reduced-motion degrades countdown to a
  non-ticking figure and the reveal to an instant state change.
- No hardcoded thresholds: anything tunable added this revamp is a `VenueConfig` column with a
  schema default, editable on `/dash/prizes`.
- Guest payload: our code ≤15KB over the framework floor; no `next/font` under `(guest)`;
  verify with `scripts/measure-guest-payload.mts` after guest surfaces.
- Commit discipline: one surface per branch off `dev`, merged back when green; every commit
  demoable. Working tree starts clean at `1867f19`.

## Surface 2 — Guest flow end to end (branch `revamp/guest-flow`)

*Exists to make waiting for food feel like something. Glance: how long do I have, what am I
choosing between?*

**Files:** `src/app/(guest)/t/[qrToken]/{page,Game,StartRun,ui}.tsx`, `game-actions.ts`,
`src/lib/prize-award.ts`, `src/lib/table-run.ts`, `src/lib/service.ts`, `src/strings/en.ts`,
new `addon/` route or outcome-inline offer.

Screens, per the brief: before-the-fire (craft pass, disabled primary, wakes on its own);
the round (streak + countdown mono, fire-time line, two dish cards, nothing else; typographic
card when no photo); rung reached (the one staged moment — countdown stops, prize named from
a read-only `decidePrizePool` preview, won price 32px accent beside struck menu price,
tonight-only line, take-or-push with the penalty stated); won (guest time vs kitchen time in
mono, prize + prices, show-your-server, ink button/pressed accent, win heading in
`font-display` — free Georgia); lost (margin stated plainly, food on its way, good loss);
not-running (unchanged copy, byte-identical rule holds); review prompt (two buttons: hand-off
and a plain decline; isolation untouched).

Behavioural fixes folded in, each with its test:
- **Countdown enforcement**: `answerPair`/`claimPrize` check the server clock against
  `endsAt`; expiry produces `FOOD_ARRIVED`/`TIMEOUT` run end; client transitions to outcome
  when the clock hits zero.
- **Redemption code collision**: per-position code derivation in `prize-award.ts` (seeded,
  deterministic per award, full 5-char keyspace) + uniqueness retry; unit test generates
  thousands without collision-by-construction.
- **Add-on restore**: outcome screens offer `en.guest.addOn` (one tap → `AddOnRequest`
  REQUESTED → floor acks → life + tier-1 extra spend become real).
- **All-games-off gates the guest route** via `getEnabledGames`, byte-identical to closed.
- **Offline**: catch rejected server actions mid-round, show `en.common.offline`, un-commit
  the tap.
- Haptics: light on answer commit, heavier on rung reached, none on wrong.
- Orphaned climb-era strings removed (ledger entry).

**Test:** existing `e2e/beat-the-kitchen.spec.ts` green; new assertions: expired clock refuses
an answer server-side; add-on request row reaches `/floor` and ack grants the life; code
uniqueness unit test; `npm test`; payload check ≤15KB over floor; full screenshot set.

*Exists to let a chef with wet hands control what the engine may give away. Glance: what

**Files:** `src/app/(kitchen)/pass/page.tsx`, `pass/actions.ts`, `src/strings/en.ts`.

  dark text, min-h-28+, the largest control in the product.
- Pool list: item, station (category), fire time (prep estimate), chip in-pool/vetoed; tap to

  anywhere; hover states removed (touch surface).

**Test:** existing pass-related E2E (depth-cap, beat-the-kitchen fixtures) green; veto
round-trips; greyscale screenshot: active load state readable by fill + position alone.
